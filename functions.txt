# 🔹 FUNCTIONS IN JAVASCRIPT (CORE CONCEPT)

👉 **Function** = a reusable block of code that performs a task.

```js
function greet() {
  return "Hello";
}
```

---

## 1️⃣ Types of Functions

---

## ✅ 1. Function Declaration

### Syntax

```js
function add(a, b) {
  return a + b;
}
```

### Key Points

* **Hoisted** (can be called before declaration)
* Has its own `this`
* Commonly used for reusable logic

```js
console.log(add(2, 3)); // 5

function add(a, b) {
  return a + b;
}
```

📌 **Interview note**: Function declarations are hoisted completely.

---

## ✅ 2. Function Expression

### Syntax

```js
const multiply = function (a, b) {
  return a * b;
};
```

### Key Points

* **Not hoisted**
* Function is stored in a variable
* Can be anonymous

```js
// multiply(2, 3); ❌ Error

const multiply = function (a, b) {
  return a * b;
};
```

📌 **Interview note**: Function expressions are created at runtime.

---

## ✅ 3. Arrow Functions (`=>`)

### Syntax

```js
const subtract = (a, b) => a - b;
```

### Key Points

* Shorter syntax
* **No own `this`**
* No `arguments` object
* Not suitable as methods or constructors

```js
const square = n => n * n;
```

📌 **Arrow functions are interview gold** — especially about `this`.

---

## 2️⃣ Default Parameters

### Problem Without Defaults

```js
function greet(name) {
  return "Hello " + name;
}

greet(); // Hello undefined
```

### Solution

```js
function greet(name = "Guest") {
  return "Hello " + name;
}
```

✔ Avoids `undefined`
✔ Cleaner code

---

## 3️⃣ Rest Parameters (`...args`)

Used when you don’t know how many arguments will be passed.

```js
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b);
}

sum(1, 2, 3, 4); // 10
```

👉 `...numbers` collects all arguments into an array.

📌 Interview difference:

* `arguments` → old, not available in arrow functions
* `...args` → modern, recommended

## 4️⃣ Key Concepts (VERY IMPORTANT)

---

## 🔹 Return vs `console.log`

### `return`

* Sends value **back to caller**
* Stops function execution

```js
function add(a, b) {
  return a + b;
}
```

### `console.log`

* Only prints output
* Does NOT return a value

```js
function add(a, b) {
  console.log(a + b);
}

const result = add(2, 3);
console.log(result); // undefined
```

📌 **Interview answer**:

> `return` gives a value, `console.log` is only for debugging.

---

## 🔹 Pure vs Impure Functions

---

### ✅ Pure Function

* Same input → same output
* No side effects
* Does not modify external state

```js
function pureAdd(a, b) {
  return a + b;
}
```

✔ Predictable
✔ Easy to test
✔ Used in React & functional programming

---

### ❌ Impure Function

* Depends on or modifies external state

```js
let total = 0;

function impureAdd(a) {
  total += a;
  return total;
}
```

📌 Interview favorite:

> Pure functions improve maintainability and testability.

---

## 🔹 Callbacks

### What is a Callback?

A function passed as an argument to another function.

```js
function greet(name, callback) {
  callback(name);
}

greet("John", function (name) {
  console.log("Hello " + name);
});
```

### Why Callbacks?

* Handle async operations
* Event handling
* Reusability

📌 Used in:

* `setTimeout`
* `addEventListener`
* APIs

## 5️⃣ ⭐ INTERVIEW FAVORITE:

### “Why do arrow functions behave differently with `this`?”

---

## 🔥 Understanding `this`

### In Normal Functions

`this` depends on **how the function is called**

```js
const user = {
  name: "Alex",
  greet: function () {
    console.log(this.name);
  }
};

user.greet(); // Alex
```

✔ `this` refers to `user`

---

### 🚨 Problem with Normal Functions (Callbacks)

```js
const user = {
  name: "Alex",
  greet: function () {
    setTimeout(function () {
      console.log(this.name);
    }, 1000);
  }
};

user.greet(); // undefined
```

👉 `this` now refers to **global object**, not `user`

---

## ✅ Arrow Functions FIX This

```js
const user = {
  name: "Alex",
  greet: function () {
    setTimeout(() => {
      console.log(this.name);
    }, 1000);
  }
};

user.greet(); // Alex
```

---

## 🔑 WHY Arrow Functions Behave Differently

📌 **Key Reason**:

> Arrow functions **do NOT have their own `this`**.

Instead:

* They **lexically bind `this`**
* `this` is taken from the surrounding scope

---

### 🧠 Interview-Ready Explanation

> Arrow functions inherit `this` from their parent scope, while regular functions have their own `this` depending on how they are called.

---

## 6️⃣ When NOT to Use Arrow Functions

❌ As object methods
❌ As constructors
❌ When you need `arguments`
❌ When dynamic `this` is required

---

## 7️⃣ One-Page Interview Summary

✔ Function declaration → hoisted
✔ Function expression → not hoisted
✔ Arrow function → no `this`, no `arguments`
✔ `return` ≠ `console.log`
✔ Pure functions → no side effects
✔ Callbacks → function as argument
✔ Arrow functions fix `this` in callbacks
