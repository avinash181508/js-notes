| Feature            | `var`                         | `let`                         | `const`                       |
| ------------------ | ----------------------------- | ----------------------------- | ----------------------------- |
| **Scope**          | Function-scoped               | Block-scoped                  | Block-scoped                  |
| **Hoisting**       | Hoisted to the top, undefined | Hoisted, Temporal Dead Zone   | Hoisted, Temporal Dead Zone   |
| **Re-declaration** | Allowed within the same scope | Not allowed in the same scope | Not allowed in the same scope |
| **Re-assignment**  | Allowed                       | Allowed                       | Not allowed (immutable)       |
| **Mutability**     | N/A                           | N/A                           | Objects/arrays are mutable    |


When to Use Each

var: Generally not recommended anymore, except for legacy code. It can cause bugs due to hoisting and lack of block scoping.

let: Ideal when you need a variable that can be reassigned and is scoped to a block (like inside a loop or condition).

const: Use this for values that won’t be reassigned (or if you have objects/arrays that won't be reassigned but whose contents can change).

## 1️⃣ Type Coercion in JavaScript

### What is Type Coercion?

**Type coercion** is JavaScript’s automatic (or implicit) conversion of one data type into another when performing operations.

JavaScript is a **loosely typed language**, so it often tries to “help” by converting types instead of throwing errors.

---

### 🔹 Types of Coercion

There are **two types**:

1. **Implicit Coercion** (done automatically by JS)
2. **Explicit Coercion** (done manually by the developer)

---

### 🔹 Implicit Type Coercion (Automatic)

#### Example: Number + String

```js
5 + "5"
```

**Result:**

```js
"55"
```

👉 Why?

* `+` operator prefers **string concatenation**
* Number `5` is coerced into string `"5"`

---

#### Example: Other Operators

```js
5 - "2"   // 3
5 * "2"   // 10
5 / "2"   // 2.5
```

👉 Why?

* `-`, `*`, `/` only work with numbers
* JavaScript converts `"2"` → `2`

---

#### Example: Boolean Coercion

```js
if ("hello") {
  console.log("Runs");
}
```

👉 Output:

```
Runs
```

Because:

* Non-empty strings → `true`
* Empty string `""` → `false`

---

### 🔹 Falsy Values (Very Important for Interviews)

These values are coerced to `false`:

```js
false
0
-0
0n
""
null
undefined
NaN
```

Everything else is **truthy**.

---

### 🔹 Explicit Type Coercion (Manual)

```js
Number("123")   // 123
String(123)     // "123"
Boolean(1)      // true
Boolean(0)      // false
```

👉 **Best practice:** Prefer explicit coercion to avoid confusion.

---

## 2️⃣ Loose Equality (`==`)

### What is `==`?

The **loose equality operator** compares two values **after performing type coercion**.

---

### Examples

```js
5 == "5"        // true
0 == false      // true
null == undefined // true
```

👉 Why?

* JS converts types before comparison.

---

### Weird (but common) Interview Examples

```js
"" == 0         // true
" " == 0        // true
[] == 0         // true
[] == ""        // true
```

👉 Reason:

* Arrays → strings → numbers (multiple coercions!)

---

### ❌ Problem with `==`

It can lead to **unexpected bugs** because of hidden coercion.

---

## 3️⃣ Strict Equality (`===`)

### What is `===`?

The **strict equality operator** compares:

* **Value**
* **Type**

🚫 **No type coercion**

---

### Examples

```js
5 === "5"      // false
0 === false    // false
null === undefined // false
```

👉 Types must match exactly.

---

### Why `===` is Preferred

* Predictable
* Safer
* Easier to debug
* Recommended by JS standards

---

## 4️⃣ `==` vs `===` (Side-by-Side)

| Comparison               | `==` (Loose) | `===` (Strict) |
| ------------------------ | ------------ | -------------- |
| Type conversion          | Yes          | No             |
| Checks value             | Yes          | Yes            |
| Checks type              | No           | Yes            |
| Safer                    | ❌            | ✅              |
| Interview recommendation | Avoid        | Always use     |

---

## 5️⃣ Common Interview Question

### ❓ Why is `null == undefined` true but `null === undefined` false?

👉 Answer:

* `==` allows special rule: `null` only equals `undefined`
* `===` checks type → different types → false

---

## 6️⃣ Best Practices (Interview-Ready Answer)

✔ Use **`===` always**
✔ Avoid relying on implicit coercion
✔ Use explicit conversion when needed

> “I prefer strict equality because it avoids unexpected bugs caused by JavaScript’s implicit type coercion.”

---

## 7️⃣ One-Line Interview Summary

> **Type coercion** is JavaScript automatically converting types.
> **`==`** compares values after coercion, while **`===`** compares both type and value without coercion.
